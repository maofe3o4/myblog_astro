网站搭好不是终点。本文是一份「上线之后怎么维护」的清单，覆盖内容更新、依赖升级、图片规范与常见故障。

## 一、日常更新内容（最高频）

写新文章的标准动作（细节见《从零写一篇笔记并发布到这个博客的完整流程》）：

1. 在 `src/content/blog/notes/<分类>/` 或 `essays/` 下新建 `.md`，文件名**全小写、ASCII 安全**；
2. 写好 frontmatter：`title` / `description` / `pubDate` / `type`，笔记补 `category` / `tags`；
3. 本地 `npm run dev` 预览，确认排版、代码高亮、公式（如有 `$$`）正常；
4. `git add -A && git commit && git push orgin main`，等 Vercel 自动重建。

> 标签里**不要带 `/`**（如 `C/C++` 写成 `C·C++`），否则会拆路由 404。

## 二、添加图片

- 文章配图直接丢 `public/images/`，统一用 **WebP**（宽 ≤1600，q82），正文用 `/images/名字.webp` 绝对路径引用；
- 顶部横幅背景图放 `public/covers/`，构建时自动纳入、按日期轮换，无需改代码；
- 正文 `<img>` 会被自动补 `loading="lazy"`，无需手加；
- **不要**放回 `src/images` 就近放，统一走 `public/images`。

## 三、改站点元信息

站名、导航、社交链接、工具页、音乐播放器都集中在 `src/site.config.ts`——改站务必先改这里，别散落到组件里。改完记得同步检查 `astro.config.mjs` 的 `site` 是否为真实域名。

## 四、升级依赖

```bash
npm outdated              # 看哪些可升
npm update                # 小版本升级
npm install astro@latest  # 大版本需先读迁移文档
```

升级后必做：本地 `npm run dev` 与 `npm run build` 各跑一遍，重点看：
- 构建后 `dist/_astro/*.css` 是否存在（缺失多半是 `vite.emitAssets` 被改掉）；
- 头部交互（主题/搜索/导航药丸）是否仍正常（脚本打包坑，见《建站流程》第五节）；
- Shiki 代码围栏语言是否全小写（`C++`→`c++`、`SQL`→`sql`）。

## 五、构建 / 部署排错速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 推送 `github.com` 失败、Connection reset | 网络到 GitHub 被重置 | 走 Gitee 镜像 / SSH 443 / GitLab 等可达链路 |
| 线上主题切换、搜索失效 | 头部脚本没打包（裸 `<script>` 被丢） | 逻辑移进 `src/lib/header.ts` 再由 BaseLayout import |
| 页面切换有缩放/残影 | 用了 `view-transition-name` 做内容入场 | 改用 `#main.is-entering` 重放 class 动画 |
| 背景图 / 雨滴不显示 | `define:vars` 内联 `import` 崩脚本 | covers 经 `data-*` 传参，脚本走打包 |
| 公式显示为纯文本 | 未接 remark-math / 缺 KaTeX CSS | 接 `remark-math`+`rehype-katex`，引入 `katex/dist/katex.min.css` |

## 六、备份与回滚

- 每篇发布即一次 git 提交，出问题 `git revert` 即可回滚内容；
- 不要手动删 `public/`、`dist/` 里的生成物；`dist/` 在 `.gitignore`，不参与版本管理；
- 大改前先 `git branch` 开分支实验，稳定后再合回 `main` 推送。

## 七、小结

维护的核心是「**只动 Markdown 与 site.config，升级先本地构建验证，推送失败换链路**」。把内容更新做成肌肉记忆，站点就会长期稳定、越用越顺手。
