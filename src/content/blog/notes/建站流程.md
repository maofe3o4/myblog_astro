本文是「建这个博客」的复盘，不是「往博客里写文章」的教程（后者见《从零写一篇笔记并发布到这个博客的完整流程》）。跟着走一遍，你能从零复刻出同样一套站点。

## 一、技术选型

核心诉求：极简、快、零运行时框架依赖、内容以 Markdown 为主、部署免费。

| 维度 | 选择 | 理由 |
|---|---|---|
| 框架 | **Astro 5** | 默认零 JS、内容站首选；Content Collections 管文章类型清晰 |
| 样式 | 原生 CSS 变量主题 | 不引 UI 库，体积小、可深度定制 |
| 渲染 | 静态（SSG） | `dist/` 纯静态，随便放哪都能跑 |
| 部署 | **Vercel** | 连 GitHub 自动构建，免费额度够用 |
| 域名 | 自有 Vercel 域名 | `astro.config.mjs` 的 `site` 改成真实域名，RSS/sitemap 才正确 |

## 二、初始化项目

```bash
npm create astro@latest        # 选 Minimal 模板
npm install
npm run dev                    # http://localhost:4321 本地预览
```

约定目录：

```
src/
  components/   头部 / 背景 / 封面 / 设置面板等
  layouts/      BaseLayout（全局外壳，客户端路由、脚本入口）
  pages/        路由：首页、博客列表、详情、标签、关于
  content/blog/ notes/(笔记) 与 essays/(随笔)，子文件夹即分类
  lib/          取文章、设置、头部交互（initHeader）等工具
  site.config.ts  站名 / 导航 / 社交 / 音乐 / 工具 等元信息
  styles/global.css  全部设计令牌与浅色/深色双主题
public/
  covers/  顶部横幅背景图（按日期每日轮换）
  images/  文章配图
```

## 三、内容模型

文章分两类（`src/lib/posts.ts` 里区分）：

- `type: essay` 随笔：按年月归档；
- `type: note` 笔记：按 `category` 归档，可带多个 `tags`。

每篇 frontmatter 必备：`title` / `description` / `pubDate` / `type`；笔记再加 `category` / `tags`。文件名即 slug，**务必全小写、ASCII 安全**，否则路由会被 Astro 小写化导致 404。

## 四、主题与外观

- 设计令牌全部集中在 `global.css`：`--brand` 主色、`--c1~--c6` 六色星辉标签色、`--font-serif` 等。
- 外观（文字风格 / 主题色相 / 下雨特效）由 `SettingsPanel` + `localStorage.sf-settings` 控制，`BaseLayout.applyLook()` 在视图过渡后兜底恢复，防止切页被重置。
- 顶部横幅背景 `AnimeBackground`：从 `public/covers/` 读取本地图，按日期轮换，无需远程图池。

## 五、客户端交互的坑（重要）

Astro 构建时，**组件内裸 `<script>` 会被静默丢弃不打包**。所有前端逻辑（主题切换、搜索、导航药丸、内容入场）都抽到 `src/lib/header.ts` 的 `initHeader()`，由 `BaseLayout` 里那段**含外部 import** 的 `<script>` 引入——只有这种写法才可靠进包。

预取不要手写：`astro:prefetch` 的 `prefetch()` 参数是 URL，策略写在 `astro.config.mjs` 的
`prefetch: { prefetchAll: false, defaultStrategy: 'viewport' }`，页面脚本只 import 自己的模块即可。

## 六、静态资源

- 所有图片转 **WebP**（宽 ≤1600，封面 q78 / 配图 q82），并补 `loading="lazy"`；
- 背景 `covers/` 与文章配图 `public/images/` 都统一 WebP，正文 `markdown` 引用 `.webp`。

## 七、部署上线

```bash
git push origin main      # 推到 GitHub（本仓库远端名为 orgin）
```

Vercel 监听 GitHub 自动重新构建。构建注意：Astro 5 静态构建需 `astro.config.mjs` 里
`vite: { build: { emitAssets: true } }`，否则 `dist` 会缺失 CSS。

## 八、小结

选型 → 初始化 → 内容模型 → 主题 → 交互（注意打包坑）→ 资源压缩 → 推送部署。这一套跑通后，日常只需要在 `src/content/blog` 里增删 Markdown，剩下的交给构建与部署。
